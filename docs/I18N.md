# Internationalisation de BioCollect

BioCollect partage son vocabulaire d’interface entre le back-office React et le client Expo au moyen du package `@biocollect/i18n`. Le français (`fr`) est la langue de repli globale et l’anglais (`en`) est fourni par défaut. Les interfaces conservent le choix de l’utilisateur, respectivement dans `localStorage` et `AsyncStorage`, puis utilisent la langue du navigateur ou de l’appareil lors de la première ouverture.

## Contrat et usage

Le contrat `Translation` décrit de façon statique l’ensemble des clés autorisées. `TranslationKey` empêche l’utilisation de clés arbitraires et `createTranslator()` produit la fonction `t()` utilisée par les interfaces.

```tsx
const { t } = useI18n();

return <Text>{t("mobile.greeting", { name: "Awa" })}</Text>;
```

Les valeurs dynamiques utilisent la syntaxe `{nom}` dans le catalogue. Si une clé est absente d’une langue chargée, le traducteur reprend systématiquement la valeur française. Si la clé est absente du contrat, le chemin de clé est retourné afin d’exposer immédiatement l’anomalie pendant le développement.

## Ajouter une langue

Une nouvelle langue est définie par **un unique fichier de traduction** sous `packages/i18n/src/locales/`, par exemple `sw.ts`. Le fichier doit implémenter `Translation` ; TypeScript signalera toute clé manquante, tout objet incomplet ou toute clé mal orthographiée. Le script `pnpm generate:locales`, lancé automatiquement avant les commandes racine de test et de vérification, détecte les fichiers `xx.ts` et construit le registre consommé par les deux applications.

```ts
import type { Translation } from "../types";

export const sw: Translation = {
  meta: { name: "Kiswahili", direction: "ltr" },
  common: { /* toutes les clés du contrat */ },
  auth: { /* … */ },
  navigation: { /* … */ },
  landing: { /* … */ },
  mobile: { /* … */ },
};
```

Le nom du fichier devient le code normalisé de la langue : `sw.ts` rend la locale `sw` disponible. Aucune modification de fournisseur, de registre applicatif ou de sélecteur n’est nécessaire. Les sélecteurs web et mobile se mettent à jour à partir de `getLocales()` au prochain démarrage.

## Tests et règles métier

Les tests `apps/mobile/src/i18n.test.ts` vérifient la résolution française et anglaise, l’interpolation, le repli français et l’exposition des langues provenant du registre généré. Les statuts métier stockés (`DRAFT`, `SYNCED`, `VALIDATED`, `SUSPECTED_DUPLICATE`, `REJECTED`) restent des valeurs de domaine : seules leurs étiquettes de présentation peuvent être traduites.

Exécutez la validation complète avec :

```bash
pnpm test
pnpm check
```
